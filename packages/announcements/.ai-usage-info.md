# @leuffen/announcements

Pflege die Daten ausschließlich in `_data/openhours.yml` gemäß
[openhours.example.yml](openhours.example.yml) und
[openhours.schema.json](openhours.schema.json). Serialisiere sie einmal im
vorhandenen `<script>`-Tag von `docs/_layouts/10_blanc.html` mit `jsonify`
vor der Komponenteninitialisierung.
Nutze `window.openhours` direkt, keine `data`- oder `source`-Properties.
Kein manuell gepflegtes JavaScript-Datenobjekt anlegen.

```liquid
window.openhours = {{ site.data.openhours | jsonify }};
```

```html

<!-- Alle Meldungen an einer Stelle -->
<leuffen-announcements>Keine aktuellen Hinweise</leuffen-announcements>

<!-- Urlaubsankündigungen im Header -->
<leuffen-announcements type="vacation" data-class="style-ribbon">
</leuffen-announcements>

<!-- Hinweise im Seiteninhalt -->
<leuffen-announcements type="info" data-class="practice-notices">
</leuffen-announcements>

<!-- Optional: Popup-Meldungen zusätzlich im Seiteninhalt -->
<leuffen-announcements type="popup"></leuffen-announcements>

<!-- Automatisches Popup einmal pro Seite -->
<leuffen-vacation-modal></leuffen-vacation-modal>

<script type="module">
  import '@leuffen/announcements';
</script>
```

Ohne Typ werden alle relevanten Meldungen angezeigt; `type` filtert nach
`vacation`, `info` oder `popup`. Urlaub zeigt nur den Titel, auch vor dem
Beginn. Hinweise und Popup-Meldungen zeigen Titel und Text im aktiven
Zeitraum. Leere Datumsgrenzen bedeuten keine Begrenzung. Der Modal-Controller
öffnet den ersten aktiven Typ `popup` oder Urlaub mit `popup: true`.

Jede Meldung ist ein eigenes DIV mit `announcement`,
`announcement-<type>` und `announcement-variant-<variant>`, optional
`has-popup` und `is-closed`. `data-class` stylt den Container.
## Leere Meldungsliste und Theme-Steuerung

Nutze für die bedingte Darstellung im Theme ausdrücklich die automatisch
gesetzte CSS-Klasse `no-announcements` am Host-Element
`<leuffen-announcements>`. Die Klasse beschreibt das Ergebnis der
aktuellen Meldungsauswahl, nicht den Inhalt des Fallbacks:

- Keine anzuzeigende Meldung: Die Klasse wird gesetzt und der ursprünglich
  im Element hinterlegte HTML-Inhalt (Fallback) bleibt sichtbar, sofern
  das Theme ihn nicht ausblendet.
- Mindestens eine anzuzeigende Meldung: Die Klasse wird entfernt und die
  Meldungen ersetzen den Fallback.
- Mit `type="vacation"`, `type="info"` oder `type="popup"` gilt der
  Zustand ausschließlich für diesen Typ; Meldungen anderer Typen sind
  dafür unerheblich. Bei fehlendem oder leerem `type` werden alle
  relevanten Meldungstypen gemeinsam berücksichtigt. Bereits eine
  anzuzeigende Meldung genügt, damit die Klasse nicht gesetzt ist.
- Urlaub kann bereits vor Beginn angezeigt werden; bei Hinweisen und
  Popups entscheidet der aktive Zeitraum. Maßgeblich ist immer, ob die
  Komponente eine Meldung anzeigt.
- Ein explizit per `_features` deaktivierter Typ setzt ebenfalls die
  Klasse, gibt eine Konsolenwarnung aus und zeigt auch den Fallback nicht an.

Beispiel für einen eigenen Meldungsbereich im Theme:

```html
<section class="practice-notice-area">
  <leuffen-announcements type="info">
    Keine aktuellen Hinweise
  </leuffen-announcements>
</section>
```

```css
/* Nur das Element ausblenden, wenn kein Hinweis angezeigt wird. */
leuffen-announcements[type="info"].no-announcements {
  display: none;
}

/* Alternativ den gesamten umgebenden Bereich ausblenden. */
.practice-notice-area:has(> leuffen-announcements[type="info"].no-announcements) {
  display: none;
}
```

Wähle die passende CSS-Regel je nach gewünschtem Layout. Soll der
Fallback sichtbar bleiben, verwende keine ausblendende Regel. Nutze
`no-announcements` auch für andere zustandsabhängige Theme-Anpassungen,
etwa Abstände oder Rahmen. Keine separate JavaScript-Abfrage der
Meldungsdaten zur Bestimmung dieses Zustands implementieren. Der Zustand
wird bei der Initialisierung des Elements berechnet; eine laufende
zeitgesteuerte Aktualisierung ist nicht Bestandteil der Komponente.

## Kompatibilität und OfficeHours

Altdaten ohne Typ bleiben Urlaub mit Popup und Schließung, sofern diese
Flags nicht angegeben sind. Expliziter Urlaub wird nur mit `is_closed:
true` als geschlossen gewertet.

```ts
import { OfficeHours } from '@leuffen/announcements';

const officeHours = new OfficeHours();
if (window.openhours) {
  officeHours.loadStruct(window.openhours);
  const infos = officeHours.getAnnouncements('info');
  const activePopup = officeHours.getActivePopup();
  const upcomingVacations = officeHours.getUpcomingVacation(null);
}
```

Weitere Beispiele und CSS-Hooks stehen in [README.md](README.md).
